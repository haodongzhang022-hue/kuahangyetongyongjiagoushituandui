# 跨行业角色层设计（0903）· HYBRID_ROLES_0903.md

> 模式：架构师通用团队模式 0903（architect-common-team-0903）
> 机器可读唯一事实源：`registry/hybrid-registry-0903.json`（本文件是人类可读版）

## 1. 为什么需要跨行业角色层

现实中的**混合型人才**：一个人同时精通两个甚至更多行业（金融工程师懂软件工程、
游戏策划懂影视语言、小说作者懂视频叙事）。纯按行业切专职角色会空转——
每个行业都养专职成本高，且跨行业任务（量化游戏、游戏宣传片、网文影视化）
需要单个角色同时具备多域知识。

## 2. 概念

允许**一个角色同时登记多个行业领域的能力**（capabilities），作为「能干活的兼职」：

- 该角色可以承接**任意已登记行业域**的任务（每次任务只属一个主域）；
- 跨行业任务（1 主域 + 1 副域）也可由单个混合角色全担（capabilities 覆盖所需行业集）；
- 能力是**声明制 + 可成长**：增删能力 = 覆盖同一 key（新增代替修改）。

## 3. 注册协议

```
memory.store {
  key:   "roster/hybrid/<角色名>",
  value: { session_id: "...", capabilities: ["finance","software"],
           proficiency: { "finance":"主力", "software":"熟练" } },
  tags:  ["0903","roster","hybrid"]
}
```

- 能力增删 = 覆盖同一 key；
- 混合注册须同时在各能力域 `roster/industry/<id>` 下关联本会话；
- 熟练度分级：主力 / 熟练 / 了解（路由解析要求 ≥ 熟练才进第 ② 档）。

## 4. 解析顺序（专职优先，硬规则）

| 档位 | 查什么 | 何时用 |
|------|--------|--------|
| ① 专职 | `roster/role/<域>·X` / `roster/industry/<id>` | 该域有专职角色 |
| ② 混合 | `roster/hybrid/*`：capabilities 覆盖任务所需行业集 且 熟练度≥熟练 | 无专职 / 专职满载 |
| ③ 兜底 | generic 主干角色 架构·X | ①②均无 |

同分多候选依次按：工作负载低 → 就近（同会话/同工作区）→ 领域包 recommended_hybrids 声明。

## 5. 跨域作业纪律（硬约束）

1. 混合角色承接某域任务 = **进入该域管线**：遵守该域领域包全部规则（事实源/门禁），**不得用另一域习惯顶替**；
2. 一次任务只属一个主域（接力卡 `industry` 字段唯一），门禁按任务所属域执行，副域知识仅作借鉴；
3. 多域规则冲突 → 显式上报（接力卡 note + 总师/人类拍板），**禁止私自取舍**；
4. 产出走该域 Issue/PR 主干与门禁，留痕署名 `@混合·<角色名>` 或 `<域>·X`。

## 6. 建议混合能力组合（seed）

| 组合 | 类型名 | 能力集 | 典型场景 |
|------|--------|--------|----------|
| 金融×软件 | 量化工程型 | finance + software | 量化系统研发（0901 实战必需） |
| 软件×游戏 | 引擎工程型 | software + game | 游戏客户端架构与玩法系统 |
| 游戏×视频 | 内容管线型 | game + video | 游戏演出/过场/宣传视频 |
| 小说×视频 | 叙事创作型 | novel + video | 剧本脚本创作/影视化 |
| 小说×游戏 | 世界观文案型 | novel + game | 游戏剧情/世界观/角色文案 |

各领域包可在 registry 的 `recommended_hybrids` 声明建议组合，供 hybrid 注册表配能力参考。

## 7. 与路由层的关系

跨行业任务在路由层的处理：主域定管线与门禁（接力卡 `industry`），副域转
`capabilities_required` → 交给覆盖能力集的混合角色（或专职+混合编组）。
